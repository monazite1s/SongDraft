# SongDraft · 多模态灵感捕捉与歌曲 Demo 协作工具

## 1. 产品定位

SongDraft 是一个面向音乐创作者的多模态灵感捕捉工具。

用户可以输入文字描述、歌词、哼唱录音、音频、图片或视频中的任意一种或任意组合，系统将零散素材整理为可解释、可编辑的创作简报，并快速生成可试听的歌曲 Demo、配乐 Demo 或旋律草稿。

产品核心不是直接生成可发行的完整歌曲，而是帮助用户完成：

> 快速记录灵感 → 整理创作方向 → 生成试听 Demo → 与创作搭档讨论和继续制作。

------

## 2. 产品价值

### 2.1 快速捕捉

用户不需要提前准备完整歌词、完整旋律或专业音乐参数。一句话、一段哼唱、一张图片都可以成为项目的起点。

### 2.2 多模态融合

不同素材不是相互独立的生成入口，而是同一创作项目中的组成部分。系统负责分析它们之间的关联、冲突和优先级，并形成统一的创作方向。

### 2.3 可解释生成

生成前展示 Creative Brief 和 Generation Plan，说明：

- 各类素材识别出了什么；
- 哪些素材会直接参与生成；
- 哪些素材会转换为文本或旋律特征；
- 当前 Provider 存在哪些能力限制；
- 哪些步骤真实执行，哪些步骤使用模拟能力。

### 2.4 协作推进

生成结果不是一次性音频，而是可以保存、比较、再次生成、分享和评论的 Demo 版本。创作搭档可以通过私密链接或二维码试听，并针对具体时间点提出反馈。

## 3. 产品形态

| 项目         | 说明                                                         |
| ------------ | ------------------------------------------------------------ |
| 主要端型     | 响应式 Web                                                   |
| 桌面端       | 完整创作、素材编辑、生成配置、版本管理和作品管理             |
| 移动端       | 极速记录文字或哼唱、上传素材、试听、分享和评论               |
| 微信内浏览器 | 支持打开分享页、试听 Demo 和提交评论                         |
| 输入         | 文字描述、歌词、哼唱录音、音频、图片、视频，至少一种，可自由组合 |
| 输出         | 歌曲 Demo、纯音乐配乐 Demo、旋律草稿                         |
| 生成长度     | 以 30～90 秒为主，用于快速验证创作方向                       |
| 生成编排     | Analyzer → Creative Brief → Capability Router → Generation Plan → Demo |
| Provider     | 支持自动路由、内置 Mock、外部 API 和用户自定义配置           |
| 协作         | 多版本、主版本、再次生成、私密分享、二维码、时间点评论       |
| 成品出口     | 复制创作包，跳转 Mureka、MiniMax 等完整成曲工具              |
| 当前策略     | 无外部 Key 时使用透明 Mock，所有模拟结果必须明确标识         |

## 4. 核心流程

```text
添加任意灵感
→ 保存文字、音频、图片或视频原始素材
→ 自动识别当前输入组合
→ 分析文字、旋律和视觉素材
→ 融合为 Creative Brief
→ 展示素材证据、冲突和处理优先级
→ 用户编辑并确认创作方向
→ 选择输出类型、生成数量和 Provider
→ Capability Router 判断当前 Provider 能力
→ 生成 Generation Plan
→ 展示真实步骤、模拟步骤、限制和降级方案
→ 创建异步生成任务
→ 输出一个或多个可试听 Demo
→ 保存版本并选择主版本
→ 基于当前版本再次生成
→ 生成私密链接和二维码
→ 创作搭档在手机端试听并提交评论
→ 评论回流至主创端
→ 复制创作包并跳转外部成品工具
```

### 4.1 输入组合

系统不要求用户预先选择“词生曲”“曲生词”或“图片生歌”等固定模式，而是根据实际素材自动识别组合。

支持的核心组合包括：

- 仅文字或歌词；
- 仅哼唱或音频；
- 仅图片或视频；
- 文字 + 哼唱；
- 文字 + 图片；
- 哼唱 + 图片；
- 文字 + 哼唱 + 图片。

### 4.2 素材处理原则

不同素材默认承担不同作用：

| 素材       | 主要作用                             |
| ---------- | ------------------------------------ |
| 文字描述   | 确定主题、情绪、风格和创作要求       |
| 原始歌词   | 确定歌曲语义和演唱内容               |
| 哼唱音频   | 提供旋律轮廓、节奏和音高参考         |
| 图片或视频 | 提供场景、色彩、氛围、配器和歌词意象 |

当素材之间发生冲突时，默认优先级为：

```text
用户明确确认的要求
>
原始歌词
>
用户哼唱旋律
>
用户填写的风格描述
>
图片或视频分析结果
>
系统默认值
```

用户可以在 Creative Brief 中调整最终处理方式。

- 关闭后主内容区自动扩展；

- Provider 配置使用全屏弹窗；
- 首页、录音、分享页和评论流程优先适配。

## 6. 页面与功能设计

## 6.1 首页

### 6.1.1 页面目标

首页用于降低创作启动成本，让用户在数秒内记录刚刚出现的灵感。

### 6.1.2 页面布局

页面中心展示类似 AI 对话产品的大型输入框，整体保持极简。

输入框支持：

- 输入文字描述；
- 输入歌词片段；
- 录制哼唱；
- 上传音频；
- 上传图片；
- 上传视频；
- 附加多个素材；
- 直接开始创作。

默认提示文案：

> 写下一句歌词、描述一个画面，或者录下刚刚想到的旋律。

输入框下方可展示：

- 录制哼唱；
- 上传素材；
- 从示例开始；
- 最近项目。

### 6.1.3 首页提交

点击提交后：

1. 创建项目；
2. 保存所有原始素材；
3. 自动判断输入组合；
4. 跳转创作台；
5. 启动对应 Analyzer；
6. 展示分析进度。

移动端增加“仅保存灵感”操作。用户可以先完成记录，稍后再进入完整创作流程。

------

## 6.2 创作台

### 6.2.1 页面目标

创作台用于完成素材整理、创作分析、生成配置、Demo 生成、版本管理和分享。

桌面端主体采用三段式布局：

```text
左侧素材构造区
→
中间生成按钮
→
右侧创作结果区
```

页面顶部提供项目级控制。

------

### 6.2.2 顶部区域

顶部区域包含：

- 项目名称；
- 自动保存状态；
- Provider 选择；
- 输出类型；
- 当前版本；
- 分享按钮；
- 更多操作。

#### Provider 选择

通过下拉框选择：

- 自动路由；
- Mock Provider；
- 已接入的外部 Provider；
- 用户自定义 Provider。

下拉菜单底部提供“管理 Provider”入口。

点击后打开弹窗，支持 Provider 配置的：

- 新建；
- 查看；
- 编辑；
- 删除；
- 启用或停用；
- 测试连接。

配置字段包括：

- 名称；
- 类型；
- Base URL；
- API Key；
- 模型；
- 能力声明；
- 是否设为默认。

API Key 不得以明文形式保存在浏览器本地。

#### Provider 能力提示

系统根据当前输入组合判断 Provider 是否支持。

例如：

> 当前 Provider 不支持同时输入歌词和哼唱。系统将先分析哼唱，并使用旋律摘要参与生成。

或者：

> 当前 Provider 不支持图片文件。本次会使用图片分析生成的视觉描述。

素材不应因为 Provider 不支持而被直接删除。系统需要标明每项素材的状态：

- 直接参与；
- 间接参与；
- 本次未使用；
- 模拟参与。

只有当前 Provider 存在明确互斥要求时，相关配置项才进入互斥状态，同时必须展示原因。

------

### 6.2.3 Version 控制

顶部展示当前版本编号和版本节点。

点击版本入口后打开版本弹窗。

版本弹窗支持：

- 展示版本父子关系；
- 标记当前版本；
- 标记主版本；
- 点击节点查看生成快照；
- 切换历史版本；
- 从历史版本再次生成；
- 设置主版本；
- 放大和缩小节点图；
- 拖动画布。

每个版本保存当时的：

- Prompt；
- 原始歌词；
- 修订歌词；
- 哼唱或音频；
- 图片或视频；
- Creative Brief；
- Generation Plan；
- Provider；
- 生成参数；
- 输出 Demo；
- 父版本。

比赛版本可先实现线性版本链或简单节点树，不需要实现复杂分支合并。

------

### 6.2.4 左侧：素材构造区

素材构造区使用 Tab 切换：

- 文字与歌词；
- 哼唱与音频；
- 图片与视频。

每个 Tab 均包含：

- 原始素材；
- 分析要求；
- 分析按钮；
- 分析状态；
- 分析结果；
- 是否参与下一次生成。

#### 文字与歌词 Tab

从上到下包含：

1. 创作描述 Prompt；
2. 原始歌词输入框；
3. 歌词处理要求；
4. 分析或整理按钮；
5. 修订结果预览。

支持：

- 输入主题和故事；
- 输入情绪、曲风和节奏要求；
- 粘贴歌词片段；
- 自动划分主歌、副歌等段落；
- 润色歌词；
- 保留原始歌词；
- 对比原稿和修订稿；
- 将分析结果写入 Creative Brief。

系统不得直接覆盖用户原始歌词。

#### 哼唱与音频 Tab

从上到下包含：

1. 旋律分析 Prompt；
2. 输入方式切换；
3. 立即录制或上传文件；
4. 音频播放器；
5. 分析按钮；
6. 旋律分析结果。

录音功能支持：

- 开始录制；
- 结束录制；
- 重新录制；
- 试听；
- 删除；
- 确认使用。

音频上传支持常见格式，并展示：

- 文件名称；
- 文件时长；
- 文件大小；
- 播放器；
- 删除和替换操作。

旋律分析结果可以包括：

- 时长；
- 速度估计；
- 音高轮廓；
- 旋律走势；
- 重复片段；
- 音域；
- 可能的记忆点；
- 分析置信度。

真实旋律分析不可用时，使用明确标识的 Mock Melody Analyzer。

#### 图片与视频 Tab

从上到下包含：

1. 图片或视频上传区域；
2. 素材预览；
3. 是否设为项目封面；
4. 分析要求；
5. 分析按钮；
6. 图片或视频转文本结果。

视觉分析结果可以包括：

- 画面主体；
- 场景；
- 色彩；
- 光线；
- 情绪；
- 动态程度；
- 推荐音乐风格；
- 推荐速度；
- 推荐乐器；
- 歌词意象。

由于部分音乐 Provider 不支持直接传入图片或视频，系统需要先调用 Vision Analyzer，将视觉素材转换为结构化描述，再由 Capability Router 判断如何参与生成。

视频在比赛版本中至少完成：

- 真实上传；
- 视频预览；
- 文件持久化；
- 封面帧或首帧提取；
- 真实或透明模拟的视觉分析。

### 6.2.5 中间：生成按钮

中间设置一个大型生成按钮，作为整个创作流程的视觉中心。

按钮文案根据状态变化：

- 分析素材；
- 生成创作简报；
- 生成 Demo；
- 基于当前版本再次生成。

Hover 时：

- 高亮左侧已选择素材；
- 高亮中间生成按钮；
- 高亮右侧结果区域；
- 使用从左到右的边框动画或光带展示创作流向。

点击生成前展示简要确认信息：

- 当前使用了哪些素材；
- 选择了哪种输出；
- 计划生成多少个结果；
- 当前使用哪个 Provider；
- 是否包含模拟步骤。

生成过程中展示异步进度和当前阶段。

失败后提供：

- 重试；
- 切换 Provider；
- 自动降级；
- 使用 Mock 完成演示。

### 6.2.6 右侧：Creative Brief 与结果区

生成前展示 Creative Brief，生成后展示 Demo 结果。

#### Creative Brief

包含：

- 创作主题；
- 情绪；
- 风格；
- 速度；
- 推荐乐器；
- 歌词概要；
- 旋律特征；
- 视觉描述；
- 素材证据；
- 输入冲突；
- 处理优先级。

用户可以直接编辑并确认。

#### 输入冲突

系统需要识别常见冲突，例如：

- 歌词表达悲伤，图片氛围明亮；
- 哼唱节奏较快，文字要求舒缓；
- 歌词字数与旋律长度不匹配；
- 当前 Provider 无法同时处理所有素材。

每个冲突展示：

- 冲突内容；
- 来源素材；
- 系统建议；
- 最终处理方式；
- 用户调整入口。

#### Generation Plan

正式生成前展示：

- 使用的 Provider；
- 各步骤执行内容；
- 每一步使用的输入；
- 真实执行或模拟执行；
- 当前限制；
- 失败后的降级路径。

#### Demo 结果

支持选择生成数量：

- 1；
- 3；
- 5；
- 10。

实际执行时可以根据 Provider 能力限制数量。核心演示至少返回两个候选结果，用于 A/B 对比。

每个结果展示：

- 封面；
- 标题；
- 播放器；
- 输出类型；
- 版本说明；
- Provider；
- 真实或模拟标签；
- 设为主版本；
- 基于此版本再次生成。

右下角提供“保存版本”按钮。

点击后将当前素材、简报、执行计划、参数和结果保存为新的版本节点。

- 当前主版本；
- 播放器；
- 创建和更新时间；
- 返回创作台；
- 再次生成；
- 分享。

下方为 Tab 区域：

- 歌词；
- 评论；
- 版本信息。

### 6.4.2 歌词

歌词 Tab 用于完整展示当前版本歌词。

支持：

- 显示主歌、副歌等段落；
- 切换原始歌词和修订歌词；
- 页面自然滚动；
- 不要求实现逐字滚动歌词。

### 6.4.3 评论

评论分为普通评论和时间点评论。

#### 普通评论

展示：

- 用户头像；
- 昵称；
- 评论内容；
- 发布时间；
- 点赞；
- 更多操作。

评论作者可以删除自己的评论。

#### 时间点评论

左侧展示纵向音频时间线。

某个时间点存在评论时：

- 生成对应节点；
- 节点旁展示评论；
- 点击节点后播放器跳转到对应时间；
- 当前播放位置附近的评论高亮。

提交评论时保存：

- 版本 ID；
- 音频时间；
- 评论内容；
- 评论者；
- 创建时间。

所有时间点评论必须绑定具体版本。

------

## 6.5 分享功能

创作者可以创建：

- 私密分享链接；
- 二维码；
- 访问 Token。

分享设置支持：

- 设置有效期；
- 允许或禁止评论；
- 撤回分享；
- 重新生成 Token。

被分享者通过链接或二维码进入移动端分享页，可以：

- 查看作品信息；
- 试听当前分享版本；
- 查看歌词；
- 提交普通评论；
- 提交时间点评论。

分享页不得暴露：

- API Key；
- Provider 内部配置；
- 未分享版本；
- 私有原始素材；
- 内部敏感日志。

分享页产生评论后，主创端显示未读提示，并将评论回流到对应版本。

------

## 6.6 成品出口

平台输出的是 Demo，而不是最终歌曲，因此需要提供明确的后续制作入口。

支持复制创作包，内容包括：

- 项目标题；
- 创作描述；
- 当前歌词；
- Creative Brief；
- 旋律分析；
- 视觉描述；
- 推荐 Prompt；
- 当前版本反馈；
- 原始素材清单。

支持导出：

- 纯文本；
- Markdown；
- JSON。

支持跳转：

- Mureka；
- MiniMax；
- 其他已配置的外部工具。

跳转前提示用户：

> 即将进入外部完整成曲工具，外部平台的费用、生成能力、版权和隐私规则由对应平台负责。

P0 必须覆盖：

## 8. 24 小时止损原则

只能降低实现深度，不能删除核心能力。

可以降低：

- 视频只分析首帧或固定关键帧；
- 旋律分析失败时使用透明 Mock；
- Vision API 不可用时使用固定结构化分析；
- Router 使用规则表实现；
- 只接入 Mock Provider；
- 自定义 Provider 仅实现配置 CRUD；
- 版本历史使用线性节点；
- 分享评论通过刷新同步；
- 移动端版本树改为列表；
- Demo 使用 30～60 秒授权样例音频；
- 局部再次生成仅模拟参数变化，不做真实音频局部编辑。

优先级始终为：

```text
流程可用
>
数据真实保存
>
状态反馈清晰
>
响应式适配
>
核心交互动画
>
装饰性功能
```

## 9. 演示主路径

1. 在首页输入一句歌词；
2. 录制一段哼唱；
3. 上传一张海边图片；
4. 进入创作台；
5. 展示三类素材分析；
6. 展示冲突、证据和优先级；
7. 编辑并确认 Creative Brief；
8. 查看 Generation Plan；
9. 展示真实步骤和模拟步骤；
10. 生成并试听两个 Demo；
11. 将其中一个设为主版本；
12. 基于主版本再次生成第三版；
13. 打开版本记录；
14. 生成二维码；
15. 手机扫码试听；
16. 提交时间点评论；
17. 主创端查看评论；
18. 复制创作包；
19. 跳转外部完整成曲工具。

## 10. 成功标准

- 文字、录音、音频、图片和视频均能真实保存和预览；
- 任意一种素材都可以单独创建项目；
- 组合输入可以生成 Creative Brief 和 Generation Plan；
- 模拟步骤不会冒充真实模型；
- 至少完成三个版本；
- 再次生成、分享和评论链路可用；
- 时间点评论可以跳转至对应播放位置；
- 390px 和 1440px 页面无横向溢出；
- API Key、私有素材和分享 Token 不泄露；
- HTTPS 环境下连续完成三次完整演示。

## 12. 透明度红线

- 不宣称一个模型同时原生理解文字、哼唱和图片；
- 不宣称平台自研了音乐生成大模型；
- 不把 Demo 描述为可直接发行的完整歌曲；
- 不展示未实际接入的 Provider；
- 不把 MiniMax Cover 描述为稳定的短哼唱续曲能力；
- Mock 音频固定显示“模拟生成 · 授权样例音频”；
- Generation Plan 必须展示 Provider、输入、限制和执行类型；
- API Key 不得在浏览器、接口响应或日志中明文出现。
