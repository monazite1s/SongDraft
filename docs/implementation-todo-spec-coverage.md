# SongDraft V5 实施 Todo · SPEC 全流程补充

> ⚠️ 本文件为 V5 设计蓝图，大部分已落地；上线前事实清单以 docs/todo.md 为准。

> 本文是 `implementation-todo.md` 的全流程补充，覆盖最新 SPEC 中已有基础设施但仍需完成 UI、权限与验收的版本历史、创作库、歌曲详情、评论和私域分享。实施时两份清单视为同一个 Todo。

## 1. 版本历史

### `VersionHistoryDialog`

- [ ] 桌面使用大尺寸 Dialog，宽度 `min(1120px, 90vw)`、高度 `min(760px, 86vh)`；H5 不开放编辑版本树，只允许在歌曲详情切换版本。
- [ ] Header 左侧显示“版本历史”和项目名，右侧只显示关闭按钮。
- [ ] 主体使用 `@xyflow/react`，包含缩放、拖动、适配视图和小地图；隐藏编辑连接点。
- [ ] 节点展示版本号、创建时间、输出类型、是否主版本和一行变更摘要；主版本使用 `brand` 边框与 Crown Badge。
- [ ] 首次打开自动 `fitView`；点击节点后平滑居中；节点拖动不得改变父子关系。
- [ ] 摘要区展示该版本的 Prompt、歌词摘要、素材数量、Brief revision、Provider 与 Demo 数量。
- [ ] Footer 左侧“删除版本”，右侧“应用到制作台”；未选中节点时均禁用。
- [ ] 删除前二次确认；删除节点后由服务端事务修复子节点 parent ID。
- [ ] 应用前检查制作台 dirty 状态；存在未保存内容时二次确认，不静默覆盖。
- [ ] 应用后恢复 Prompt、歌词、音频、图片、Brief 和 Demo，但不自动发起生成任务。
- [ ] 删除当前应用版本后保留制作台内容，只从历史树移除节点。
- [ ] `GET /api/projects/[id]/versions` 返回节点与 parent ID，前端负责布局，不持久化画布坐标。
- [ ] 主版本不可直接删除，需先指定新主版本；一个项目至多有一个主版本。

## 2. 创作库 `/works`

- [ ] 创作库只展示项目，一项目一卡片；多个历史版本不得生成多张作品卡。
- [ ] Header 显示“创作库”、项目数和“新建项目”；查询条支持关键词、状态、输入组合和更新时间排序。
- [ ] 桌面 3 列、窄屏 2 列、H5 单列；服务端分页，每页 12 条，条件写入 URL。
- [ ] Card 展示 16:9 封面、标题、两行简介、状态、输入类型、主版本时长和更新时间。
- [ ] 无封面使用中性音符占位；点击 Card 进入 `/works/[id]`，菜单提供“进入制作台、分享、归档”。
- [ ] 列表只读取项目与主版本摘要，不加载全部版本和 Demo Assets。
- [ ] 保存新主版本后刷新对应 Card 的封面、简介、时长和更新时间。
- [ ] 已归档项目默认隐藏，可通过状态筛选查看并恢复。
- [ ] 空库提供“记录灵感”和“直接创建项目”；无查询结果只提供清空筛选。

## 3. 歌曲详情与详情侧栏

### `SongDetailPage`

- [ ] `/works/[id]` 使用上下布局：顶部信息区，底部“歌词/评论”Tabs。
- [ ] 信息区展示封面、标题、作者、描述、当前版本、生成来源和统一播放器。
- [ ] 右上角依次为“分享、编辑、历史版本、更多”；分享访问者不显示管理操作。
- [ ] “编辑”把当前版本导入制作台；历史切换后刷新封面、音频、歌词和评论，不进入制作台。
- [ ] 歌词保留原始换行，正文最大宽度 720px；无歌词显示克制空状态。

### `SongDetailSheet`

- [ ] 创作台点击 Candidate 后打开 480px 右侧 Sheet；工作区此时形成素材、成果、详情三栏。
- [ ] Sheet 复用全屏详情的数据类型、播放器、歌词摘要和评论组件。
- [ ] Sheet 顶部提供“进入全屏详情”；切换 Candidate 时更新音频源并重置播放时间。
- [ ] 打开同一音频详情不重新加载音频，不打断正在播放的进度。

## 4. 统一播放器与时间点评论

### `SongDraftAudioPlayer`

- [ ] 结果卡、详情 Sheet、全屏详情和分享页使用同一个播放器组件。
- [ ] 控件包含播放/暂停、波形、进度、当前时间/总时长、音量与倍速。
- [ ] 同一页面只允许一个播放器发声；新播放器播放时暂停旧播放器。
- [ ] Player 暴露 `currentTimeMs`、`seekTo(ms)` 与 `onTimeUpdate` 给评论时间轴。
- [ ] 临时 URL 过期时重新获取 COS 签名 URL；失败后显示可重试错误。
- [ ] 支持 Space 播放/暂停、左右方向键前后 5 秒；输入框聚焦时不拦截快捷键。

### `TimecodedComments`

- [ ] 评论表单默认读取播放器时间，但用户必须点击“使用 01:23”显式锁定时间点后才能发送。
- [ ] 表单包含时间 Badge、Textarea、取消时间点和发送按钮；未锁定时间时按钮禁用。
- [ ] 评论最多 1000 字；失败保留输入，提交中禁止重复发送。
- [ ] 评论按 `atMs ASC, createdAt ASC` 显示为纵向时间轴。
- [ ] 每条显示时间、头像、用户、内容与创建时间；点击时间调用 `seekTo` 并播放。
- [ ] 当前播放时间接近评论 ±2 秒时高亮节点，不自动滚动打断阅读。
- [ ] 作者可删除本人评论，项目所有者可删除项目内评论；删除使用软删除。
- [ ] 切换版本后只读取对应 version 评论，禁止混用不同音频的时间点。
- [ ] 空状态文案：“播放到某个位置，留下第一条时间点反馈”。

## 5. 分享与访问白名单

### 分享管理

- [ ] 分享 Dialog 展示链接、二维码、有效期、复制按钮、是否允许评论和访问者管理。
- [ ] 原始 token 只在创建时返回；数据库继续只保存 token Hash。
- [ ] 所有者可查看已授权用户、授权时间与最近访问时间，并可撤销访问。
- [ ] 分享链接失效或撤销后显示专用失效页，不泄露作品标题与封面。

### 首次访问与权限

- [ ] 未登录用户访问有效链接时先登录/注册，再通过安全 return URL 返回。
- [ ] 已登录用户首次通过有效 token 访问时创建白名单授权；后续访问以授权记录为准。
- [ ] 分享链接不等于永久权限；被撤销用户即使持有旧链接也返回 403。
- [ ] 分享用户权限仅为收听和评论，不显示分享、编辑、历史、原始素材或版本管理。
- [ ] 分享页不显示内部 Sidebar，中心展示歌曲信息、播放器与歌词/评论 Tabs。
- [ ] H5 保证单手播放和评论，输入框不得被软键盘遮挡。
- [ ] 所有 COS 地址由服务端按当前授权签发短期 URL。

### 权限数据模型

- [ ] 新增 `share_access_grants`：`id, share_id, project_id, user_id, granted_at, last_accessed_at, revoked_at`。
- [ ] 采用能避免同一作品多链接产生重复授权的唯一约束，并为 `user_id + project_id` 查询建立索引。
- [ ] `comments.share_id` 改为可空：站内详情评论不要求分享链接，分享页评论保留 share ID 审计。
- [ ] 评论权限统一进入 `CommentService`；项目所有者与已授权协作者可读写，其他用户拒绝。
- [ ] 撤销访问不删除历史评论，但该用户不能再进入作品页。

## 6. 补充测试与验收

- [ ] 版本树点击节点自动居中；未选节点时删除/应用禁用。
- [ ] 应用版本遇到未保存草稿会确认，取消后工作区不发生变化。
- [ ] 删除节点后子节点仍可访问，主版本约束保持正确。
- [ ] 创作库一个项目只出现一张 Card，切换主版本后 Card 摘要刷新。
- [ ] 全屏详情、Sheet、分享页播放器的播放时间与 seek 行为一致。
- [ ] 未锁定时间点不能评论；点击评论时间可跳转播放。
- [ ] 切换版本后评论严格隔离。
- [ ] 用户 A 通过有效链接获得访问后可再次访问；撤销后立即 403。
- [ ] 用户 B 仅复制稳定详情 URL、未通过有效分享流程时不可访问。
- [ ] 分享访问者看不到任何作品管理操作或私有 COS 原始地址。
